# 物序前端

Taro 4 + React 18 + TypeScript + SCSS。微信小程序首发，H5 用于快速预览。按需引入 NutUI React Taro 的 Popup；核心页面和组件按 Figma 实现。

## 本地开发

建议 Node.js 22 LTS 或更新的兼容版本，首次运行 `npm ci`。

```sh
cd frontend
npm ci
npm run dev:h5
```

打开 http://127.0.0.1:10086/。常规窗口单列显示，640px 及以上支持两列物品卡片；宽屏内容居中且限制阅读宽度。尺寸矩阵和验收边界见 [多尺寸适配说明](../docs/RESPONSIVE.md)。

```sh
npm run dev:weapp
```

用微信开发者工具导入 **frontend 文件夹**，配置已指向 `dist/weapp/`。`project.config.json` 使用测试 AppID `touristappid`；真机预览需要替换成自己的小程序 AppID。开发配置关闭 URL 校验，接入真实 API 后应开启校验并配置 HTTPS 合法域名。

## 当前功能

完整操作步骤与验证范围见 [Mock 功能与验收说明](../docs/FRONTEND_MOCK.md)。

- 首页：当前空间累计/已知投入、当前/已知日均投入、搜索、分类、状态过滤、日均参与物品追溯。
- 详情：真实日均成本、履历、事件与操作时间、支出新增和更正、编辑、默认在用、出售/淘汰及更正、零回收确认。
- 录入：仅名称即可建档；可选物品图片与独立凭证；退出表单保留本地草稿。
- 截图校对：固定示例结果、图片选择/移除/预览、字段编辑、未知值、赠品、相同型号提示、跳过或独立建档、逐件确认、保存幂等与部分结果反馈。
- 分析、记录、空间：空间隔离、类别投入追溯、状态分布、操作历史、家庭创建/演示加入、成员角色、个人物品迁入家庭、可恢复删除。

首页保留 Figma 的「当前日均投入」，按当前空间每件在用物品的日均投入求和，排除已处置与回收站；存在缺失时展示「已知日均投入」和待补充件数。详细口径见 PRD v1.2。

物品购入后默认持续在用，从购买日起按日历天数分摊，购买当天计 1 天，出售或淘汰时截止。已取消闲置状态及切换入口；读取本地旧数据时自动将闲置档案（含回收站）转为在用，保留购买日期、金额、支出和历史，不重置计时。

## Mock 与边界

默认开启 mock。初次使用会写入个人空间 4 件物品与 2 个示例家庭；数据在当前浏览器或小程序设备中持久化。初始日期按首次使用当天生成，方便复现 Figma 的持有天数。时间统一按 UTC+8、金额按整数分、展示日均两位小数。

**截图没有调用真实 AI，也没有上传到云端。** 固定示例结果不会根据用户选择的图片改变，界面有明确说明。图片选择和「演示识别流程」用于验证交互；本地已提供逐图成功/失败与重试场景，真实识别和字段来源需后端接入。示例里金额分摊必须经用户核对。

家庭角色仅在本地 mock 仓储校验，不构成服务端安全隔离。本机可生成和撤销邀请码、模拟其他成员加入，结果持久化到成员列表。真实登录、跨设备同步、邀请链接/撤销/过期、实时成员权限变化及并发控制需后端实现。本地示例邀请码为 `DEMO-FAMILY`，加入前需要确认目标家庭及角色。

回收站不自动清除，不提供永久删除；未擅自确定恢复期限。家庭迁出、管理者转交、解散等 PRD 待确认功能未开放。草稿保留在本机，存储期限尚未设定；生产图片应迁往受控附件服务。

## 对接 FastAPI

正式接口需求见 [后端 API 需求与联调约定](../docs/API_REQUIREMENTS.md)。下列 ledger 接口仅为当前演示预留；正式接入资源接口时，需要同步调整数据适配、状态管理和分页加载。

复制 `.env.example` 到 `.env`，设置 `TARO_APP_USE_MOCK=false` 和 `TARO_APP_API_BASE_URL` 后重新构建。页面通过 `services.ts` 的仓储边界访问数据，mock 和 HTTP 共用领域模型。

当前预留的联调契约（尚无后端实现）：

- `GET /api/v1/ledger` → 当前用户可访问的 `Ledger` 快照。
- `POST /api/v1/ledger/commands` → `Command` 联合类型；返回更新后的快照。
- 403 → 权限变化，409 → 版本冲突；页面保留输入，不静默覆盖。
- 新增/导入的 `key` 应在服务端实现幂等；修改命令包含 `revision`；金额均为整数分，未知为 `null`。

服务端必须重新执行鉴权、可见范围限制、幂等及版本校验。请求地址、鉴权和字段转换集中在 `services.ts`；正式资源接口的分页查询、详情与汇总独立加载，还需要同步修改 `store.tsx` 和页面的数据加载流程。

## 工程结构

```text
config/           Taro、Vite 与双端构建配置
src/assets/       从 Figma 下载的图片、SVG 与来源清单
src/pages/index/  物品、分析、记录、空间
src/pages/detail/ 详情与生命周期
src/pages/import/ 截图导入校对
src/components.tsx 共享交互原语与 NutUI Popup
src/forms.tsx     建档、支出、处置表单
src/domain.ts     成本、日期、金额与校验
src/commands.ts   mock 命令、版本、权限及审计规则
src/services.ts   本地持久化与 HTTP 仓储
tests/            PRD 业务规则测试
```

## 验证

```sh
npm run typecheck
npm test
npm run build:h5
npm run build:weapp
```

测试覆盖 PRD 金额/日期样例、未知与零元、处置固定天数、持续按天计时和旧版状态迁移、重复保存、权限、迁移、版本冲突、删除恢复、支出更正，以及空间日均汇总。不以 H5 预览或编译成功替代真机验收；仍需用微信开发者工具及 iOS/Android 真机检查图片选择、键盘、安全区、返回与离线恢复。

## 多尺寸布局

小程序开启 resizable，监听窗口变化及键盘高度，按系统状态栏、胶囊和底部安全区调整导航与弹层。小程序样式保留逻辑 px 并通过媒体查询重排，避免平板/折叠内屏将整页 rpx 字号放大。H5 与小程序共用重排规则；35 组 H5 视口检查及微信原生待验收项见 [适配记录](../docs/RESPONSIVE.md)。
