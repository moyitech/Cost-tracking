空间页已采用左对齐空间名片和分组管理列表；「创建家庭空间」「加入家庭」统一放在顶部「全部空间」面板。顶部账户头像与个人空间、本人家庭成员头像同步；家庭头像独立，仅管理者可更换。头像选择和默认恢复均需保存后生效；存在未保存修改时，点击取消或关闭会提示保存，可选择「保存并退出」「不保存并退出」或「继续编辑」，没有实际变化则直接关闭。沿用现有 COS 上传与签名读取接口；真实接口要求后端迁移至 `a6d925c104ab`。

空间选择面板内可返回列表、创建家庭或查看邀请说明；微信扫一扫只接受当前小程序的邀请页路径，并进入现有邀请确认流程。H5 不模拟原生扫码；Mock 模式提供明确的演示邀请入口。

头像选图使用原图，iOS / Android 微信优先在原生 `cropImage` 中固定按 1:1 裁剪。开发者工具、Windows / Mac 微信及未知宿主直接使用内置裁剪器，避免能力探测误报导致原生接口一直不回调；手机微信仅在不支持或原生调用失败时自动回退。原生裁剪成功后，读取结果失败最多重试两次；宽高仅差 1 像素时在已确认的裁剪结果上修正为正方形。结果读取、校验或修正失败会提示重新选图，不再打开第二个裁剪器。内置裁剪器在同一面板中使用原生 MovableView 拖动、Slider 缩放和 Canvas 导出实际正方形图片，预览和导出共用图片解码与源像素坐标，适配带旋转信息的照片。H5 保留拖动、缩放与键盘微调。用户主动取消原生裁剪时直接返回，不再打开内置裁剪器。确认裁剪才更新预览，点击「保存头像」才压缩和上传；取消选图、取消裁剪或关闭编辑均不覆盖已保存头像。任何回退均不直接上传原图。

头像和物品图片上传前校验正方形像素，最长边 512px、不放大小图、最大 256 KiB；优先 WebP，不支持则使用 JPEG，并逐级调整质量、必要时缩小至不低于 128px。凭证和订单截图仍使用既有 2 MiB / 8192px 规则。头像与物品图片上传缓存分别带处理版本，旧缓存不能跳过新规则。Mock 保存同样处理后的内容，小程序写入持久文件，H5 保存数据地址，不保存原始临时文件。既有文件 ID 不强制重新处理；后端接口和数据库不变。

### 界面精简（2026-10-26）

目标是降低文字密度：每个区块只保留一个视觉焦点，同一事实只出现一次，去掉的可见说明在辅助功能标签中保留。配色、玻璃底栏、弹层几何与键盘避让不变。

- 金额统一由 `Amount` 渲染：¥ 与小数缩小变淡；行内次要金额为整数时省略 `.00`。
- 首页汇总卡只突出日均持有成本，点数字进入在用物品；副行为累计（缺失时为已知投入）与件数，「N 件待补充」进入待补充筛选。「全部 / 在用 / 已处置」状态筛选常驻显示并带件数；从汇总卡或分析页进入的细分筛选（待补充、已出售等）显示为下方可清除的标签，同时选中所属分段。
- 物品为小红书式瀑布流：1:1 方形封面（照片铺满、预设插图留白、无图显示名称首字），下方名称最多两行，再是日均与持有天数；缺资料时改为琥珀色「补充价格和购买日期」。封面同高，错位来自文字行数；每张卡放进最短的一列，差距不足一行时放左列，保持最新在前的阅读顺序。已处置物品的封面左上角显示「已出售/已淘汰」并降低饱和度。列数按瀑布流实际宽度计算（卡片最小约 168px）：窄屏为 `min(窗口, 960) − 32`，640px 起再减去汇总栏（内容宽度的 40%，限制在 264～320px）和 20px 间距，见 `src/masonry.ts`。
- 详情把图片、名称、状态与所属空间、日均合并为顶部区；更多操作用竖排「⋮」，避免与小程序右上角胶囊的「•••」混淆；「购买与记账信息」「支出明细」并入生命周期，可编辑者点条目打开对应更正表单；只列已知数据，缺失项为一个补全入口。
- 记录按月分组；分析用比例条、可点图例（标注统计日期）和「日均成本最高」前 5 件替代成段文字。
- 空间页、空间切换、成员、邀请与头像弹层删去装饰性说明，保留隐私、权限与有效期信息。

所有可点按钮使用统一按压态（小程序 `hover-class`，H5 另有 `:active`），玻璃底栏除外。提交成功提示改为对应结果：「已移入回收站」「已恢复」「已迁入家庭」「家庭已创建」「权限已更新」「已移除成员」「昵称已更新」「头像已更新」「已加入家庭」；删除、移除成员和放弃修改的确认按钮为红色。

表单草稿只在内容与档案不同时保存，打开后直接关闭不留草稿；恢复了未保存内容时顶部提示一行。草稿记录的版本落后于档案时：未改动则直接换成最新资料；新增支出、首次处置只新增记录，自动改用新版本；编辑物品、更正支出或处置会提示「档案已在别处更新」，由用户选择保留填写或采用最新资料，选择前不能保存（PRD AC18）。保存遇到 409 时同样提示，不再要求重新打开档案。次按钮未改动时为「取消」，有改动时为「放弃修改」并需确认；处置表单保留「稍后补充」。

## 真实后端联调

阶段 A 已连接资源接口，不再使用 `/ledger` 或 `/ledger/commands`。复制 `.env.example` 为 `.env` 后配置：

```dotenv
TARO_APP_USE_MOCK=false
TARO_APP_API_BASE_URL=https://wx.frp.geekyuu.com/api/v1
# 仅 H5 开发联调；发布前留空。小程序不使用此身份。
TARO_APP_H5_DEV_IDENTITY=demo
```

修改构建环境变量后重启 dev 命令/重新构建。小程序通过 `Taro.login()` 获取微信 code，然后调用后端微信登录；H5 当前使用显式配置的开发测试身份。二者是不同用户，数据不会互相复制。相同真实微信账号可跨设备读取自己的档案。

- access/refresh token 按 API 地址保存；401 时串行刷新，同一批请求共用一次刷新；重试保留原幂等键与版本。网络失败不清除登录凭证或表单。
- 物品列表按空间/商品名/状态分页；首页汇总和分析从完整空间统计接口读取，记录、详情历史、回收站各自分页。
- 原 Mock 数据与云端数据、草稿分开存储，不自动上传本机演示档案。普通表单保留本地草稿。
- 金额从整数分映射，详情和卡片使用服务端 metrics；未知值不转换成零。
- 微信 `wx.request` 不支持 PATCH，因此小程序编辑使用 `POST /items/{id}/update` 和 `POST /items/{id}/expenses/{expense_id}/update`，语义与 PATCH 一致，仍需 If-Match。H5 使用原 PATCH 接口。
- 写入成功后刷新列表、完整空间汇总、分析和记录；详情单独读取最新费用和历史。刷新失败不把已经成功的写入当作失败重试。
- AI 截图导入已接入真实异步任务，家庭创建/加入及迁移仍暂不开放。

### Emoji 图片选择器

### 图片直传流程

选择图片后保持本地草稿，点击保存时先在设备本地处理图片，再申请 `/files/uploads`，客户端 PUT 处理后的二进制到 COS，再调用 `/files/{id}/complete`。确认后的 file_id 才关联物品；API Bearer token 不会发送给 COS。已上传文件与上传状态按当前用户暂存，网络重试复用已确认的 file_id。图片 URL 到期时重新向后端取签名地址。

物品照片、凭证和 AI 截图共用 `local-image.ts` / `image-processing.ts`：选原图避免微信预先有损压缩。物品照片先裁剪为正方形，再按头像相同的 512px / 256 KiB 规则处理；凭证和 AI 截图长边超过 8192 px 才等比缩小，不放大小图。为控制手机画布内存，额外限制画布最多 16777216 像素（RGBA 约 64 MiB；不含解码、编码临时内存），超出时继续等比缩小。优先编码 WebP，检查真实文件头；不支持或静默输出 PNG 时回退 JPEG，透明区域统一铺白。质量从 85% 降至 75%、65%，仍超过各自大小限制则按 80% 等比减小尺寸并重新尝试；不无限降质，失败时提示换图或裁剪。上传前再次核对字节数、格式和尺寸。处理串行执行，复用画布并在结束后释放大尺寸缓冲；JPEG 编码产生的临时文件立即删除，不新增持久化的压缩副本。

AI 竖向截图高宽比达到 3 时提示分段上传，进度界面也提示长账单分段；不自动拆图或改变现有每批最多 9 张的规则。DeepSeek 会自行缩放图片，满足文件大小和单边限制不保证超长截图的小字识别率。小程序使用页面内隐藏的 2D Canvas，H5 使用本地 Canvas；WebP 是否可编码按运行时真实输出判断，仍需 iOS/Android 微信真机验收。后端保留自身上传验证，不负责转码。

微信后台需在 request 合法域名添加后端与 COS 域名，在 downloadFile 合法域名添加 COS 域名。此流程不使用 `wx.uploadFile`，因此不需要 uploadFile 合法域名。

H5 默认来源为 `http://127.0.0.1:10086`。COS Bucket CORS 需允许该来源及 `http://localhost:10086`，方法 PUT/GET/HEAD，允许头 Content-Type。后端 `.env` 的 `CORS_ORIGINS` 也需允许 H5 来源。只把后端穿透域名填进 COS CORS，不能授权本地 H5 页面。

### 真实截图导入

首页「AI 截图导入」→ 选择截图 → 开始识别 → 在与手动添加相同的表单里修改预填值 → 点击“保存物品”。多件以左右滑动卡片展示，也可点击上一件/下一件；保存后自动切到下一张。已取消、已全额退款的商品直接过滤，不显示跳过卡片。只有点击保存后才计入物品与统计。

手动添加和 AI 卡片复用 `src/item-fields.tsx`，包含图片、名称、实付、日期、分类及折叠的更多信息。整批截图通过一次 AI 请求联合识别，重复截图和滚动重叠商品去重，同款不同订单保留。识别完成后仅显示表单，不提供原图、识别说明或历史导入入口。

AI 选图、上传缓存和所有卡片字段只在页面内存保存，远处卡片卸载也不丢填写；切后台保留，离开添加页清空，再次进入需重新上传。识别完成后不轮询，返回前台只恢复未完成任务查询。系统相册、拍照不会清空。上传失败重用当前页已上传文件，AI 失败整批重试，不生成空白占位卡片。

进度为上传 0–30%、排队 30–40%、联合识别 40–95%，收到有效结果才达到 100% 并显示表单；不展示虚构剩余时间。保存仍通过 patch + commit，遇到响应丢失先核实保存状态，避免重复建档。数量不明及重复物品继续在对应卡片提示。普通手动表单的草稿规则保持原样。

服务端需要独立运行 `uv run python -m app.worker`。如果停在等待识别，检查 Worker 是否运行；普通 API 进程不执行耗时模型请求。原图与正式物品图片分别管理，导入不会自动把含订单信息的截图公开为物品附件。

## 缓存与时间线交互

真实模式采用全空间离线缓存，按 API 地址和账号隔离。微信端将资料快照与图片写入用户文件目录；H5 将资料和 Blob 写入 IndexedDB。启动先恢复快照，所有已授权空间的物品、支出、历史、回收站和家庭成员都同步到本地，浏览列表、详情、分析、记录、成员和已缓存空间切换不依赖接口请求。新增、修改、删除、邀请及 AI 识别仍需联网。

统一自动更新，不再提供数据同步设置卡片或模式开关，也不读取旧的仅手动更新偏好。前台每 60 秒检查版本，进入前台与网络恢复时触发检查并合并重复请求；后台暂停，失败按 60/120/240/300 秒退避。顶部刷新按钮和下拉刷新可立即重试；首次无缓存、资料或图片缺失时仍尝试修复。在线保存立即更新缓存，并校准服务端版本。

启动先显示可用资料，主要同步完成后延后 750ms 异步预热预设目录和两套缩略图，最多同时加载 2 张，不等待预热完成才开放页面，也不下载原图。预热直接复用内存和持久缓存，按账号与目录版本合并重复任务；同一版本成功后不在每次心跳重复执行。预热缺图不会触发新的全量同步；失败静默停止本轮队列，下一次同步成功、回到前台或网络恢复后补齐。切后台、断网、账号或版本变化时不再启动旧任务的后续下载，已发起的下载可能完成，账号隔离和迟到响应保护仍生效。Mock 使用内置预设，不执行网络预热。

## 家庭管理

空间页可创建家庭、查看扫码／分享加入说明、管理成员与生成邀请；创建和加入均需填写家庭昵称。家庭成员面板支持本人改名，管理者可调整其他非管理者的编辑者／查看者角色或移除成员。加入不会公开个人物品。

邀请默认编辑者、7 天内多人可用；选择角色并生成后，展示小程序码和「分享给好友」。分享使用内置 1000×800 PNG 封面，邀请页兼容 token／scene，登录后直接显示卡片并确认加入。生成码失败只重试当前邀请，不重新创建；返回角色选择后再次生成才创建新邀请。时间按设备本地时区显示中文日期和剩余天／小时。被移除者必须使用移除后新生成的邀请。空间切换、页面重新显示与写入失败会刷新权限；迁移会失效来源和目标缓存。

验证：类型检查、前端测试、H5 创建/切换/邀请/跨开发身份成员显示/改名/改角色已通过。微信分享卡片、冷启动登录后接受邀请及 iOS/Android 跨账号加入待真机验收。每次前端修改后必须执行 `npm run build:weapp`。

邀请分享封面随前端打包到 `assets/invitation-cover.png`，同时由后端提供公开 HTTPS 地址供微信分享读取，以兼容开发者工具的图片加载。修改封面时同步更新 `backend/app/assets/invitation-cover.png` 和分享 URL 的版本号。邀请码图片写入小程序临时用户目录后显示，关闭弹窗会清理对应文件。


家庭成员面板采用深绿渐变家庭标题与简洁列表：管理者优先，同角色本人优先，显示昵称首字头像与“我”标记。昵称编辑通过独立弹窗按需打开；成员右侧显示角色徽标，管理者点击徽标进入权限面板，修改权限及移除前明确确认。编辑者／查看者只可修改本人昵称。成员异步加载与状态变化继续通知外层 Sheet 重测高度，嵌套弹窗使用原生 RootPortal。
