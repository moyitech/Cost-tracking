## 2026-10-23 22:10 录屏：点击输入框后键盘自动收起

按 20fps 拆帧：点击商品名后键盘完整弹出，弹窗仍在原位，键盘稳定约 0.3 秒；随后弹窗按键盘高度整体上移、缩短并出现“收起键盘”，键盘在同一帧开始下落，约 0.15 秒后弹窗回到原位。第二次点击商品名、点击价格（数字键盘）都重复同一顺序。键盘不是被代码主动收起，而是在弹窗避让布局生效的瞬间失焦。

- 原因（由时序推断）：共用 Sheet 内输入框开启 `alwaysEmbed`（iOS 同层渲染）后，原生输入框挂在页面渲染层中；收到键盘高度后修改弹窗 `bottom`、最大高度和滚动区高度，iOS 重新挂载该输入框，输入框随即失焦。19:31 录屏数字键盘自行消失时同样同时存在 `alwaysEmbed` 与弹窗避让；20:57 录屏去掉 `alwaysEmbed` 后键盘稳定，但文字不随滚动。
- 处理：保留 `alwaysEmbed`，文字和光标继续随表单滚动；改由微信原生 `adjust-position`（默认值）在键盘弹起时整体上推页面，`cursor-spacing` 留 24px。小程序弹窗不再随键盘高度移动或改变尺寸，输入框聚焦期间暂缓应用窗口尺寸变化，失焦后再更新。移除输入框级键盘高度监听和小程序滚动定位；全局键盘高度事件仍只写入开发记录。
- 移除 `holdKeyboard`：点击输入框以外区域按微信默认行为收起键盘（数字键盘没有完成键），小程序不再显示“收起键盘”。H5 的 visualViewport 避让、滚动定位和“收起键盘”保持不变。
- 验证：TypeScript、96 项前端测试、微信与 H5 生产构建、5 个 WXSS 文件编译通过；上一轮 H5 键盘回归脚本对新构建通过。编译产物中输入框只保留 `always-embed` 与 `cursor-spacing`，不再设置 `adjust-position=false` 和 `hold-keyboard`。浏览器和开发者工具都不能模拟 iOS 同层输入与系统键盘，仍须真机验收。
- 真机复测：用户已在 iOS 微信真机确认点击输入框后键盘不再自动收起，测试正常。Android 尚未回归。

## 布局策略

| 场景 | 处理方式 |
| --- | --- |
| 320～360 窄屏 | 汇总数值可换行，缩小部分留白；日期/金额表单改为单列；来源图片单列；长名称、金额不撑破容器 |
| 361～639 常规窗口 | 单列卡片随容器伸缩；H5 全部宽度保持逻辑字号，窄屏通过重排适配，不再等比缩小文字 |
| 640 及以上折叠内屏、平板 | 首页和记录使用两列；主要内容限制阅读宽度，详情/导入最多 760 逻辑像素；弹层最多 560 逻辑像素 |
| 327×327 等短屏 | 缩减底栏高度；弹层标题固定，内容区独立滚动；可以到达末尾保存和退出按钮 |
| 小程序顶部 | 优先读取 `getWindowInfo()` 和 `getMenuButtonBoundingClientRect()`；动态计算状态栏高度、导航高度和胶囊避让，失效时回退 |
| 弹窗顶部 | 共用 Sheet 最大高度扣除状态栏与胶囊导航区，再留 8px 间隔；44×44px 关闭按钮完整位于胶囊下方。H5 扣除顶部安全区，表单内容独立滚动，底部保存区保持固定 |
| 小程序底部 | 从系统 safeArea 计算底部留白；正文预留底部操作栏空间 |
| 首页导航 | 52px 圆角导航内容区，选中态在按钮内部；手势安全区使用页面底色，不铺满整块白色；普通底栏总高为 56px + 安全区，短屏为 52px + 安全区 |
| 窗口变化 | 监听 `onWindowResize`，折叠/展开、PC 缩放时重新读取布局信息 |
| 键盘出现 | 小程序由输入框 `adjust-position` 整体上推页面，弹窗不随键盘移动或改变尺寸（iOS 同层输入框会因周围布局变化失焦）；H5 监听 visualViewport |
| 小程序样式单位 | 关闭整页 px → rpx 放大；以逻辑 px 配合百分比、Flex、Grid 和媒体查询重排；图标尺寸同步使用逻辑 px |
| H5 宽屏预览 | 内容最多 960 像素；原来 440 宽即固定到 390 像素的规则已移除；浏览器外框规则不影响小程序 |

DPR 描述物理像素密度，不应按 DPR 再放大排版尺寸。图片清晰度和实际高 DPR 设备显示仍需在原生环境验收。

### 液态玻璃底栏视觉

- 底部导航采用接近 Apple Liquid Glass 的视觉效果：22px 背景模糊、1.6 倍饱和度、68%～80% 浅色半透明填充、边缘高光及随选项移动的透镜。只应用于导航层，正文卡片保持原有设计。
- 沿用上述紧凑高度、安全区和至少 44×44 逻辑像素的点击区域。四个入口均实际点击验证，高亮与选中按钮对齐。
- 不支持背景模糊时使用接近不透明的浅色填充；浏览器支持并启用“减少透明度”或“增强对比度”偏好时改为不透明底色与更强边框；“减少动态效果”偏好下停用滑动和按压动画。已添加相应媒体查询，尚未逐个系统设置实测。

### 底栏拖动选择

- 在底栏任一选项上按住左右拖动，高亮连续跟随手指；松手吸附到最近的选项并切换页面。拖动预览期间不切换正文，普通点击继续有效。
- 小于 8px 的移动作为点击处理；以竖向移动开始的手势取消选择。已开始拖动后可左右折返或跨越多个选项；高亮限制在四个选项内，松手位置远离底栏则取消。触摸中断、多指触摸也会取消。
- H5 使用 Pointer Events，识别到横向拖动后才捕获指针，防止普通点击丢失；拖动结束屏蔽随后的兼容点击，避免切回起点。微信端使用 Taro 触摸事件与实时容器测量，处理快速松手早于测量返回的情况。
- 新增 8 项手势测试，覆盖小幅移动、连续跟随与松手吸附、双向折返、按下位置偏移、竖向取消、兼容点击抑制、边界取消和不同宽度；全套测试共 30 项通过。

### 对照录屏补充透镜动效

- 按下时透镜鼓起、图标与文字放大；拖动速度影响横向拉伸；松手后弹簧回弹并吸附。拖动期间保留原页面，释放才提交目标页。
- 透镜内部通过 9 段连续采样实现中心放大、边缘压缩。外部图案按胶囊圆角轮廓裁切，避免经过图标时出现矩形缺口；外沿采样与原图连续，避免跳过笔画。材质保留透色、白色边缘高光和轻微色散高光。
- H5 使用 `requestAnimationFrame`；微信端按 30fps 调度，仅在动画未稳定时更新。图案使用缓存组件，装饰层不接受点击且从无障碍树隐藏，原有四个导航按钮继续负责交互。实际设备帧率尚未测量。
- “减少动态效果”下关闭弹簧与光学变形；“减少透明度”/“增强对比度”下恢复不透明选中态；不支持 `clip-path` 时回退为普通滑动选中态。系统偏好回退已编码，尚未逐项实机验收。
- 新增 6 项光学与弹簧测试：30/60fps 收敛、延迟帧稳定、静止采样、中心放大及边缘连续性、宽窄屏边界、圆角外侧完整性。全套 **36 项测试通过**，TypeScript、H5 和微信小程序构建通过。
- 本轮 Chrome 实际验证双向拖动、移出取消和普通点击；327×327、320×568、717×781 的按压透镜未出界，390×844 + 34px 模拟安全区中透镜底部为 805px，安全区始于 810px。正文无横向溢出，控制台未捕获错误。证据位于 `output/navigation/lens-results.json`、`lens-pressed-safe34.jpg` 及 `lens-宽x高.jpg`。

## 设计依据

布局适配采用 apple-design skill 中的布局与滚动检查原则，将它们用于 Taro/微信小程序：

- `layout.md › Adaptability / Size classes`：按实际可用空间决定布局，而非按设备型号决定布局。
- `layout.md › Guides and safe areas`：关键内容与操作避开系统区域。
- `scroll-views.md › Best practices`：超出边界的内容可以滚动，避免同方向多层滚动互相截断。
- `materials.md › Liquid Glass`：玻璃材质仅用于浮动导航和控制层；以常规磨砂效果保持标签可读。当前底栏为跨平台视觉近似。
